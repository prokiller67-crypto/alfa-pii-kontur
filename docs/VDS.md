## Защита и эксплуатация

- Снаружи открыты SSH 22, HTTP 80 и HTTPS 443; UFW включён.
  Порт приложения 8091 слушает только localhost; Redis наружу не опубликован.
- HTTP перенаправляет на HTTPS. Путь ACME на 80 нужен для продления сертификатов.
- Ключи сгенерированы на VDS, `.env` имеет права 0600. В Git и ZIP их нет.
- Включён только официальный анонимный `/process`; `/v1/*` и метрики требуют
  `X-System-Id` и `X-API-Key`. Публичная страница интерфейса предназначена
  для локальной демонстрации; анонимный удалённый `/v1/mask` не разрешён.
- Логи запросов Nginx/Uvicorn отключены. Журнал приложения содержит типы данных,
  время и класс ошибки без исходного текста или traceback.
- Redis хранит шифротекст AES-256-GCM с TTL; лимит 512 МБ, noeviction.
  Перезапуск Redis удаляет сопоставления. Произвольные перезапуски во время
  проверки не нужны; CPU и RAM тарифа не гарантируют заявленный SLA.
- Docker и Nginx включены при старте ОС; контейнеры имеют `restart: unless-stopped`.
- Сертификат для IP выдан Let's Encrypt до 30 сентября 2026; он короткоживущий.
  Certbot 5.8 установлен в `/opt/certbot`, `certbot.timer` запускает обновлённый
  бинарник, deploy-hook проверяет Nginx и перечитывает сертификаты.
  Дополнительный DNS-сертификат действует до 22 декабря 2026.
- Тест продления IP-сертификата (`renew --dry-run --run-deploy-hooks
  --no-random-sleep-on-renew`) прошёл; Nginx проверен и перечитан.
  Первая попытка на тестовом ACME вернула `Service busy; retry later` с
  `Retry-After: 3`; повтор после задержки завершился успешно.

Документация Let's Encrypt:
[IP и короткие сертификаты в Certbot](https://letsencrypt.org/2026/03/11/shorter-certs-certbot).
Автоматическое продление обязательно: короткий срок не продлевается сам по себе.
