# Что требуется для зачёта

Источник: [онбординг организаторов](https://reg.vibecoding-hackathon.ru/ds.pdf),
раздел 7 и приложения A/B. Срок на портале: **23 сентября 2026, 23:59 МСК**.

1. Загрузить ZIP с исходниками и успешно пройти автоматическую проверку кода.
   Датасеты, зависимости, сборки и `.git` в архив не входят.
2. Опубликовать `POST /process` и сохранять URL доступным для внешнего прогона.
   Вход: `{"payload":"...","payload_id":"..."}`, успешный ответ: `{"result":"..."}`.
   Первый запрос с новым ID маскирует данные, запрос с полученной маской и тем же
   ID точно восстанавливает оригинал. Повторы должны быть безопасными.
3. Пройти проверку на эталонном наборе всех 17 типов ПД и сложных предложений.
   ТЗ задаёт качество 95%, нагрузку около 1000 запросов/с в течение 5 минут и
   целевую задержку до секунды. Жёсткий таймаут клиента — 10 секунд.
   Клиент делает до двух повторов, учитывает `Retry-After` при 429 и прекращает
   прогон после пяти невалидных запросов подряд. Постоянные 429 означают, что
   сервис не справился с нагрузкой.
4. Отправить итоговую работу в отдельном разделе «Загрузка решения»:
   ZIP до 2 ГБ, презентацию до 50 МБ, ссылку на код и URL сервиса.
   Описание до 1000 символов и скринкаст до 3 минут необязательны.

Сообщение «Ваше решение принято» подтверждает приём формы. Оно не подтверждает
прохождение внешнего теста или победу. Балл проверки исходников не является
процентом точности маскирования. Vercel допустим как способ развёртывания;
важна доступность и фактическая работа API под нагрузкой.
