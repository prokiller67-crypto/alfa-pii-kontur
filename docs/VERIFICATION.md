# Проверка первого прототипа — 22 сентября 2026

Здесь разделены локальные измерения и проверка публичного API. Первая официальная
проверка исходников завершилась успешно: лучший результат **9910 баллов**,
0 BLOCKER, 7 CRITICAL, 3 MAJOR. Вторая проверка после смены маски дала тот же
результат; третья после структурного рефакторинга — 9895 баллов и 12 замечаний.
Подробности в [OFFICIAL_CHECKS.md](OFFICIAL_CHECKS.md),
[OFFICIAL_CHECKS_2.md](OFFICIAL_CHECKS_2.md) и
[OFFICIAL_CHECKS_3.md](OFFICIAL_CHECKS_3.md).
Отчёт не содержит показателей точности или нагрузки; веса критериев и точные
эталонные маски остаются неизвестными.

  точное восстановление, отсутствие исходных значений в логах/ошибках, политику системы,
  изоляцию систем, криптографическую привязку записей, TTL, заполнение и отказ хранилища.

  онбординга и обратное восстановление. Те же результаты проверены по
  опубликованному адресу после обновления checker-политики.
- В третьей попытке большой проход детектора и обработчик API были разделены
  на меньшие функции. Локальная проверка сложности улучшилась, но официальная
  оценка снизилась до 9895. Код этих двух модулей возвращён к версии второй
  попытки. Для следующей проверки удалён неиспользуемый адаптер Upstash;
  рабочие Neon и Redis сохранены. Текущий проход: 83 теста пройдены, один
  live-тест Neon пропущен без специальной переменной окружения.
- Новый Vercel deployment успешно прошёл публичный и авторизованный цикл
  запросов. Один полный HTTP-ответ восстановления с ноутбука занял 2.455 с;
  итоговые задержки всё ещё требуют измерения на организаторском прогоне.
- Набор разработки: **52 примера**, exact typed-span F1 **1.0**,
  восстановление в трёх форматах **156/156**.
- Дополнительный набор: **22 примера**, F1 **1.0**,

- **Все 74 примера являются синтетическими и использовались при настройке.** Это регрессия,
  а не независимая оценка и не подтверждение официального требования 95%.
- Docker собран и запущен: четыре Uvicorn-процесса и общий настоящий Redis.
- Авторизованные `/v1/mask` → `/v1/restore` проверены через HTTP; анонимный `/metrics` даёт 401.
- Prometheus multiprocess aggregation проверена: после 10000 запросов виден общий счётчик всех процессов.
- Браузер: маскирование, восстановление, пример публичной информации; ширина 390 px без
  горизонтального переполнения (scrollWidth = clientWidth = 390).

## Последняя нагрузочная проверка

Машина: **Apple M5, 10 CPU, 16 GiB RAM**. Docker VM: 10 CPU, около 7.65 GiB RAM.
Генератор и сервис работают на одном компьютере. Клиент aiohttp + uvloop,
48 параллельных цепочек. Тексты различаются номером обращения в одном шаблоне:
ФИО, паспорт, email, телефон. Полный кэш детектора не получает один и тот же текст;
словари и морфологический кэш могут прогреваться.

| Измерение | Результат |
|---|---:|
| HTTP-запросы, включая оба направления | 10000 |
| Длительность | 5.411 с |
| Средняя пропускная способность | 1847.9 запросов/с |
| p50 | 9.49 мс |
| p95 | 76.66 мс |
| p99 | 105.07 мс |
| Максимум | 178.64 мс |
| HTTP 200 | 10000 |
| Корректные пары маскирование/восстановление | 5000 / 5000 |

Это короткий closed-loop прогон, не доказательство пятиминутного SLA на внешнем эталонном наборе.
Предыдущий HTTPX-генератор дал 423–542 RPS и оказался ограничением измерения;
эти числа нельзя выдавать за предел производительности сервиса.

## Большой текст

Синтетический документ: **441779 символов**, 6000 строк, новые ID и email в строках.
Маскирование: **3.721 с**, восстановление: **0.027 с**,
оба ответа HTTP 200, полное совпадение оригинала. Проверяемые исходные ФИО и домены email
не остались в маске. До исправления разбор границ предложений повторялся для каждого фрагмента
и расходовал таймаут regex; теперь индекс границ строится один раз на окно, а regex-таймаут
не включает последующую обработку Python.

**Задержка маскирования большого текста превышает целевую секунду.** Количество токенов не измерено,
поскольку токенизатор не задан; 441779 символов нельзя объявлять 100000 токенами.

## Что остаётся до заявки на победу

1. Получить формат эталонной маски и методику span-based Levenshtein от организаторов.
2. Собрать отдельную, не использованную при настройке выборку с вариантами ФИО/адресов и негативными примерами.
3. Ускорить длинные документы, определить токенизатор и добавить корректный TPS.
4. Выполнить официальный внешний 5-минутный прогон 1000+ RPS. API уже опубликован на Vercel + Neon Free; подробности в VERCEL.md.
5. Проверить перезапуски/отказы в целевой инфраструктуре, добавить HA по требованиям финальной архитектуры.
6. Получить детализацию 7 CRITICAL и 3 MAJOR из официальной проверки; подготовить
   финальную презентацию и скринкаст, подать VCS URL и deployed URL. Проверка ZIP пройдена.
