## Последняя нагрузочная проверка

Машина: **Apple M5, 10 CPU, 16 GiB RAM**. Docker VM: 10 CPU, около 7.65 GiB RAM.
Генератор и сервис работают на одном компьютере. Клиент aiohttp + uvloop,
48 параллельных цепочек. Тексты различаются номером обращения в одном шаблоне:
ФИО, паспорт, email, телефон. Полный кэш детектора не получает один и тот же текст;
словари и морфологический кэш могут прогреваться.

| Измерение | Результат |
|---|---:|
| HTTP-запросы, включая оба направления | 10000 |
| Длительность | 5.411 с |
| Средняя пропускная способность | 1847.9 запросов/с |
| p50 | 9.49 мс |

| Максимум | 178.64 мс |

Это короткий closed-loop прогон, не доказательство пятиминутного SLA на внешнем эталонном наборе.
Предыдущий HTTPX-генератор дал 423–542 RPS и оказался ограничением измерения;
эти числа нельзя выдавать за предел производительности сервиса.

## Большой текст

Синтетический документ: **441779 символов**, 6000 строк, новые ID и email в строках.
Маскирование: **3.721 с**, восстановление: **0.027 с**,
оба ответа HTTP 200, полное совпадение оригинала. Проверяемые исходные ФИО и домены email
не остались в маске. До исправления разбор границ предложений повторялся для каждого фрагмента
и расходовал таймаут regex; теперь индекс границ строится один раз на окно, а regex-таймаут
не включает последующую обработку Python.

**Задержка маскирования большого текста превышает целевую секунду.** Количество токенов не измерено,
поскольку токенизатор не задан; 441779 символов нельзя объявлять 100000 токенами.

## Что остаётся для доказательства требований

1. Получить формат эталонной маски и методику span-based Levenshtein от организаторов.
2. Собрать отдельную, не использованную при настройке выборку с вариантами ФИО/адресов и негативными примерами.
3. Ускорить длинные документы, определить токенизатор и добавить корректный TPS.
4. Выполнить официальный внешний 5-минутный прогон 1000+ RPS. API уже опубликован на Vercel + Neon Free; подробности в VERCEL.md.
5. Проверить перезапуски/отказы в целевой инфраструктуре, добавить HA по требованиям финальной архитектуры.
6. Получить детализацию 3 CRITICAL и 2 MAJOR из официальной проверки. Финальная
   заявка с ZIP, презентацией, VCS URL и deployed URL уже сохранена на портале;
   скринкаст оставлен пустым как необязательное поле.
