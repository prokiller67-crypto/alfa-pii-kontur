# Контур — Alfa PII Proxy

Рабочий прототип для трека «Высоконагруженный прокси для LLM».
Находит персональные данные в русском тексте, маскирует их и восстанавливает.
Реализует официальный `POST /process`; есть интерактивная демонстрация, политики систем,
локальная модель NER, морфология, зашифрованное хранилище замен и метрики.

**Статус на 23 сентября:** проверка исходников — **9990 баллов**, но публичный
API на Vercel **отключён**. Провайдер заблокировал команду по fair use;
`/healthz` и `/readyz` возвращают HTTP 402 `DEPLOYMENT_DISABLED`.
Новая v5 подготовлена и прошла проверку, но deployment отклонён. Для полноценной
готовности нужен доступный хостинг и повторная внешняя проверка API.

**Кандидат v6:** исправлено распознавание паспорта после обычного пробела и
ложное срабатывание внутри буквенно-цифрового кода. **113 тестов пройдено**,
но v6 ещё не отправлен на проверку и не опубликован.
[Подробности и проверки](docs/PASSPORT_BOUNDARIES_V6.md).

Попытки 19, 20 и 21 сохранили 9990: **0 BLOCKER, 0 CRITICAL, 2 MAJOR**.
В v5 исправлена очистка принадлежащего приложению хранилища при ошибке/отмене,
явно выключен traceback в журнале ошибок и выровнен возврат ASGI middleware.
**101 тест пройден:** 99 обычных и 2 на настоящем Neon PostgreSQL.
Код кандидата — тег
[`submission-reliability-v5`](https://github.com/prokiller67-crypto/alfa-pii-kontur/tree/submission-reliability-v5).

На портале сохранена предыдущая итоговая заявка v4 с 9990. Её исходники и
презентация остаются поданными, но указанный URL сейчас недоступен. Последний
успешный deployment до блокировки соответствовал `submission-quality-v4`.
Исторические 25/25 точных циклов и 50 HTTP 200 не доказывают доступность сейчас.
Независимое качество 95% и внешний пятиминутный SLA не подтверждены.

## Быстрый запуск

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/).

```bash
uv sync --frozen
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 uv run uvicorn pii_proxy.app:app --host 127.0.0.1 --port 8090 --no-access-log --no-proxy-headers
```

Открыть [локальный интерфейс](http://127.0.0.1:8090) или [Swagger](http://127.0.0.1:8090/docs).
Данные обрабатываются на компьютере; внешняя LLM не подключается. Модель и словари
устанавливаются вместе с зависимостями, во время обработки сетевой NLP-вызов не нужен.
Локальный режим использует один процесс и состояние в памяти; остановка процесса уничтожает сопоставления.

## Контракт организаторов

```json
POST /process
{"payload":"Клиент Иванов Иван Иванович, паспорт 4509 123456","payload_id":"demo-1"}
```

Ответ содержит ровно `{"result":"..."}`. Первый запрос маскирует.
Отправьте полученный `result` как `payload` с тем же ID — получите оригинал.
Повтор оригинала снова возвращает маску; повтор маски снова возвращает оригинал.
Другой текст под занятым ID даёт 409, без утечки исходного текста.

Дополнительные API:

- `POST /v1/mask` — явное маскирование, координаты и типы фрагментов.
- `POST /v1/restore` — восстановление точной маски или токенов в изменённом тексте.
- `GET /healthz`, `GET /readyz` — состояние процесса и зависимостей.
- `GET /metrics` — Prometheus; доступ требует разрешённой системы либо локального demo.

В `/v1/*` локальный demo принимает `mode`: `token`, `shape` или `partial`.
Для аутентифицированных систем формат задаётся политикой; укажите совпадающий `mode`.
`shape` скрывает символы и сохраняет пунктуацию, `token` сохраняет смысл через типы сущностей,
`partial` оставляет часть реквизита видимой и подходит только при явном выборе такой политики.
Для checker-режима выбран `partial`: он воспроизводит пример маски из онбординга
`И. И. И.` / `45** ****56`. Остальные системы используют собственные политики.

## Настройка новой системы — 5 предложений

1. Скопируйте `config/policies.example.json` и добавьте систему с именем, `api_key_env`, `types`, `mode` и `restore`.
2. Поместите API key в указанную переменную окружения, а путь к JSON — в `PII_POLICIES_FILE`.
3. При необходимости задайте `min_types`, `requires` или выключите систему через `enabled: false`.
4. Передавайте `X-System-ID` и `X-API-Key` в запросах; после изменения конфигурации перезапустите сервис.
5. Используйте новый `payload_id` для новой операции или после смены политики и восстанавливайте до истечения TTL.

## Четыре процесса и Redis в Docker

```bash
uv run python scripts/init_local_env.py
docker compose up --build -d
```

Скрипт создаёт `.env` с ключами и правами 0600, не печатает их и не заменяет существующий файл.
Compose по умолчанию слушает **только 127.0.0.1:8091**; Redis наружу не опубликован.
Все процессы используют один ключ и Redis, который содержит зашифрованные записи с TTL.
Кэш Redis не сохраняется на диск; перезапуск Redis уничтожает активные сопоставления.
Метрики агрегируются между процессами через Prometheus multiprocess mode.

Для локального теста совместимости с проверяющей системой, которая не описывает API key:

```bash
PII_CHECKER_MODE=1 docker compose up -d
```

Это открывает `/process` без API key на локальном опубликованном порту.
Для внешнего прогона нужен доступный из интернета URL. Поддержаны Docker на сервере
и Vercel с общей базой Neon; наличие VPS не обязательно.
Не включайте публичный checker-режим для обычной рабочей интеграции.

Остановка тестовых контейнеров: `docker compose stop`.

## Воспроизводимая проверка

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 uv run pytest -q
uv run ruff check .
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 uv run python scripts/evaluate.py
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 uv run python scripts/evaluate.py --challenge
uv run python scripts/benchmark.py --url http://127.0.0.1:8091 --pairs 5000 --concurrency 48 --unique
uv run python scripts/large_text.py --url http://127.0.0.1:8091
uv run python scripts/package.py
```

Два набора качества — 52 и 22 самостоятельно размеченных синтетических примера.
Оба уже использовались при настройке, поэтому их нельзя называть независимой проверкой или
подтверждением официальных 95%. Нагрузочный скрипт меняет номер обращения в одном шаблоне;
для проверки повторяемых текстов уберите `--unique`. Он считает оба HTTP-запроса каждой пары,
измеряет задержки целиком на клиенте и проверяет точное восстановление.

ZIP создаётся в `artifacts/alfa-pii-source.zip`. В нём нет `.env`, зависимостей, моделей,
PDF, результатов прогонов и бинарников. Небольшие синтетические фикстуры — часть исходников тестов.
Скрипт проверяет, что реальные локальные ключи не попали в архив.

## Компоненты NLP

Используются [Natasha / Slovnet](https://github.com/natasha/natasha) и
[pymorphy3](https://github.com/no-plagiarism/pymorphy3), а также контекстные правила для реквизитов.
Модель Natasha обучена на новостных текстах; её качество в банковском домене нужно проверять отдельно.
Зависимости зафиксированы в `uv.lock`; лицензии upstream-компонентов сохраняются в установленных пакетах.
